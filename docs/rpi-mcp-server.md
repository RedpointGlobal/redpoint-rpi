# RPI MCP Server

[< Back to Home](../README.md)

## Overview

The **RPI MCP Server** exposes the RPI Integration API as Model Context Protocol tools, so AI clients can work through RPI's documented API rather than a bespoke integration. It reads through the Integration API and never writes to an RPI database.

The **agent runtime** is an optional RPI native agent that reaches RPI only through those tools.

| Workload | What it is | Reached by | Setting |
|---|---|---|---|
| `rpi-mcpserver` | the tool surface | MCP clients | `redpointAI.mcp.enabled` |
| `rpi-aiserver` | the agent runtime | your own client in namespace | `redpointAI.agentRuntime.enabled` |

Each is enabled on its own. The tool server stands alone; the runtime requires the tool server.

```
MCP client  ->  rpi-mcpserver  ->  rpi-integrationapi  ->  RPI
agent runtime  ->  rpi-mcpserver  ->  rpi-integrationapi  ->  RPI
```

## Enable the tool server

```yaml
redpointAI:
  mcp:
    enabled: true
    defaultClientId: <your-rpi-tenant-guid>
    oauthClientId: <integration-api-oauth-client-id>
```

Add `RPI_AI_OAuth_Client_Secret` to the standard RPI Secret.

A tool server consumes no model, so `redpointAI.model` is not required for it.

`secretsManagement.provider` must be `kubernetes` or `csi`.

## Enable the agent runtime

```yaml
redpointAI:
  model:
    ApiBase: https://<your-openai-name>.openai.azure.com/
    ApiVersion: <azure-openai-api-version>
    ChatGptEngine: <chat-model-deployment-name>
  agentRuntime:
    enabled: true
```

Add `RPI_NLP_API_KEY` to the standard RPI Secret. It is the same Azure OpenAI key natural language rule building uses. The session signing key is generated by the chart.

## Configuration

| Value | Default | Purpose |
|---|---|---|
| `redpointAI.mcp.enabled` | `false` | Deploy the tool server |
| `redpointAI.mcp.defaultClientId` | `""` | RPI tenant GUID, sent as `X-ClientID`. Required when enabled |
| `redpointAI.mcp.oauthClientId` | `""` | Integration API OAuth application. Required when enabled |
| `redpointAI.mcp.auth.required` | `true` | Require a bearer token on the MCP endpoint |
| `redpointAI.mcp.auth.proxy.enabled` | `false` | Run every call as one service account |
| `redpointAI.mcp.auth.proxy.user` | `""` | Service account username. Required with `auth.proxy.enabled` |
| `redpointAI.agentRuntime.enabled` | `false` | Deploy the agent runtime. Requires `redpointAI.mcp.enabled` |
| `redpointAI.agentRuntime.azureResourceName` | `""` | Azure OpenAI resource name. Derived from `redpointAI.model.ApiBase` unless that endpoint is not the standard Azure form |
| `redpointAI.agentRuntime.storage.size` | `50Gi` | Volume holding the runtime database |
| `ingress.hosts.rpimcpserver` | `rpi-mcpserver` | Tool server hostname |

Secret keys:

| Key | Required when |
|---|---|
| `RPI_AI_OAuth_Client_Secret` | `redpointAI.mcp.enabled` |
| `RPI_MCP_Proxy_Pass` | `redpointAI.mcp.auth.proxy.enabled` |
| `RPI_NLP_API_KEY` | `redpointAI.agentRuntime.enabled` |

See [Secrets Management](secrets-management.md).

Both workloads are fixed at one replica and refuse any other value at render. The agent runtime uses a persistent volume provisioned by the chart.

## Authentication

### Per user

The default. The MCP client sends the caller's own RPI access token:

```
Authorization: Bearer <token>
```

RPI applies that person's permissions. A tool the caller's role does not allow returns a message saying so. A user-scoped tool is never run under the service account; without a token it is refused.

Any token RPI accepts works, including one from a federated provider. Where the deployment federates, the server publishes `/.well-known/oauth-protected-resource` and a client that speaks the MCP OAuth flow signs in on its own. See [Single Sign-On](single-sign-on.md) for provider configuration.

### Service account

```yaml
redpointAI:
  mcp:
    auth:
      proxy:
        enabled: true
        user: <service-account-username>
```

Every call runs as that RPI user and per user identity is discarded. Use it for system automation only. Requires `RPI_MCP_Proxy_Pass`.

### Turning the check off

`redpointAI.mcp.auth.required: false` accepts unauthenticated calls and runs them under the service account. Set it only where the endpoint is unreachable from outside a trusted boundary, and publish the endpoint accordingly.

`oauthClientId` and its secret are required in every mode. The server registers no tools without them.

## Endpoint

The tool server is published through ingress. The agent runtime is internal to the namespace and has no ingress.

```
https://<ingress.hosts.rpimcpserver>.<ingress.domain>/mcp
```

The hostname follows the same rule as every other service: the value in `ingress.hosts` is prepended to `ingress.domain`, unless it contains a dot, in which case it is used as an FQDN.

## MCP client

```json
{
  "mcpServers": {
    "rpi": {
      "type": "http",
      "url": "https://<mcp-host>/mcp",
      "headers": { "Authorization": "Bearer ${RPI_TOKEN}" }
    }
  }
}
```

Drop the `headers` block in service account mode. Reference the token through an environment variable rather than pasting it.

Run the `verify_connection` tool first. It reports whether the token was accepted and makes a live API call.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `/mcp` returns 503, no tools listed | A required variable is missing. `GET /health` reports `mcp: degraded` and names them |
| Every call returns 401 | No bearer token, or it has expired |
| A tool reports your role is not permitted | RPI denied the call. Cluster-wide tools need a cluster administrator |
| `helm upgrade` fails naming a value | A required setting is unset. The message names the path and the fix |
